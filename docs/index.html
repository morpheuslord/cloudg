cloud graphing · AWS / Azure / GCP

Map the cloud. Scan it. Merge everything.

cloudg collects your infrastructure into a graph, fans out to the security scanners you already trust, and merges every finding against 28 compliance frameworks — or skips the scanning entirely and aggregates outputs you already have.

GitHub PyPI Markdown docs

# Installation

# core: graph engine, normaliser, renderers, ingest
pip install cloudg

# cloud SDK extras — pick what you collect from
pip install cloudg[aws]        # boto3 / aioboto3
pip install cloudg[azure]      # Azure management SDKs
pip install cloudg[gcp]        # google-cloud-asset
pip install cloudg[all]

The cloud SDKs are optional extras. The core package alone still gives you the graph engine, ontology, findings normaliser, report renderers and cloudg ingest — enough to aggregate existing scan results on a machine with no cloud credentials at all.

The scanners are not Python dependencies. Prowler, ScoutSuite, Checkov and Trivy are separate executables. Install whichever subset you want — cloudg detects what is on PATH and skips the rest with a warning. install.sh / install.bat set up everything; the Docker image bundles all four.

Python 3.11 or newer.

# The pipeline

collectasync, all providers
→
graphreachability, attack paths
→
scanprowler · scout · checkov · trivy · iam
→
normalisededupe · score · map
→
reportHTML · JSON · RDF · RAG · TF
  • Collect — asyncio collection from every configured provider, account and region in parallel. Regions auto-discover with --regions all.
  • Graph — assets and network edges become a directed NetworkX graph; BFS from the internet node finds exposed resources, blast-radius scoring estimates what an attacker could reach from each node.
  • Scan — the enabled scanners run concurrently over the same inventory. Each one is optional.
  • Normalise — findings are deduplicated within and across scanners, rescored against CVSS, and mapped to compliance controls.
  • Report — interactive HTML, findings JSON, topology in three formats, RDF ontology, RAG chunks, Terraform recreation.

Every phase degrades gracefully: a missing binary, an unreachable provider or a failed exporter logs a warning and the rest continues.

# cloudg run — full pipeline

cloudg run -p aws --regions us-east-1
cloudg run -p all --regions all              # everything, everywhere
cloudg run -p aws --scanners prowler,trivy   # subset of scanners
cloudg run -p aws --regions us-east-1 --terraform
FlagMeaning
-p, --provideraws, azure, gcp or all; repeatable
--regionsall for auto-discovery, or a comma-separated list
--scannerssubset of prowler,scoutsuite,checkov,trivy,iam; defaults to scanners.enabled in config
--iac-dirdirectory for the IaC scanners (Checkov, Trivy fs)
--imagescontainer images for Trivy
--ontology / --no-ontologyRDF export (on by default)
--rag-export / --no-rag-exportRAG chunks (on by default)
--terraform / --no-terraformTerraform recreation (off by default)
-o, --outputoutput directory, ./reports by default

When no IaC directory is configured but --terraform is on, the IaC scanners target the generated Terraform recreation of the live infrastructure — Checkov audits your actual cloud, not whatever directory cloudg happens to run from.

# collect & scan — the phases alone

# assets + network edges only, no scanners
cloudg collect -p aws --profile prod --region eu-west-1

# scanners only, no collection
cloudg scan -p aws --scanners prowler,checkov --iac-dir ./terraform

collect writes assets and edges for graph building; scan runs the selected scanners concurrently and writes raw-findings.json.

# cloudg ingest — bring your own scan results

Already ran the scanners somewhere else — CI, a scheduled job, another machine? Feed cloudg their native output files and it does the aggregation half of the pipeline: normalisation, cross-scanner deduplication via the check-equivalence rulesets, compliance mapping and report generation. No scanners execute and no cloud credentials are needed.

cloudg ingest \
  --prowler ./prowler-output/ \
  --scoutsuite ./scoutsuite-report/ \
  --checkov ./results_json.json \
  --trivy ./trivy-image.json --trivy ./trivy-fs.json \
  -o ./reports
FlagAccepts
--prowlerASFF JSON/JSONL file, or Prowler's -o output directory
--scoutsuitethe scoutsuite_results_*.js file, or the --report-dir directory
--checkova checkov --output json file, or a directory containing it
--trivytrivy image|fs --format json file or a directory of them; image vs filesystem is detected from ArtifactType
--formathtml, json or all (default)

Every flag is repeatable, and any combination or subset of tools works — one tool alone or all four together. Generate the inputs with:

prowler aws -M json-asff -o ./prowler-output
scout aws --report-dir ./scoutsuite-report --no-browser
checkov -d ./iac --output json > results_json.json
trivy image --format json myrepo/app:latest > trivy-image.json
trivy fs --format json --scanners vuln,misconfig,secret ./iac > trivy-fs.json

Ingest runs no collection, so outputs that need live assets — topology, ontology, RAG, Terraform — stay empty. When credentials are available, combine both: collect() + ingest_reports() + analyze() through the Python API.

# cloudg report — re-render

cloudg report -i ./reports/findings.json --format html

Re-generates HTML / JSON / SVG reports from a previous run's findings.json without touching the cloud or the scanners.

# Deduplication & combination rulesets

Findings merge in two conservative passes:

  • Within a scanner — keyed on (scanner, check ID, resource): the same check re-reported for the same resource collapses to one finding.
  • Across scanners — merged only when the normalised titles match and both check IDs resolve to the same canonical semantic ID in rules/check_equivalence.yaml.
- id: aws-s3-default-encryption
  title: S3 bucket default encryption at rest
  checks:
    prowler:  [s3_bucket_default_encryption]
    checkov:  [CKV_AWS_19]
    trivy:    [AVD-AWS-0088]

Checks not in the equivalence map are never merged across scanners: the safe failure mode is visible duplication, not silently dropping a scanner's coverage. A merge keeps the highest severity and unions source tools and frameworks — a merged finding reads source_tool: "prowler, checkov". This works with whatever subset of tools contributed; fewer tools simply means less to merge.

# Compliance frameworks

Findings are tagged with framework controls in four tiers, most precise first:

  • Whatever the scanner itself reports (Prowler ASFF, Checkov check IDs).
  • Exact check-ID lookup against the shipped rulesets — generated from Prowler's public compliance data: 28 frameworks, 4,166 controls, 10,236 check mappings across AWS, Azure and GCP. CIS 5.0 per cloud, NIST 800-53 rev 5, NIST CSF 2.0, PCI DSS 4.0, SOC 2, HIPAA, GDPR, ISO 27001:2022, MITRE ATT&CK, AWS FSBP, and more.
  • Regex pattern rules for scanners with no compliance metadata.
  • A small built-in fallback table.

Your own framework is a YAML file in the rules directory:

framework: MY-FRAMEWORK
controls:
  - id: "MF-1.1"
    title: "Storage is encrypted"
    patterns: ["encrypt.*rest"]        # regex tier
    checks: ["s3_default_encryption"]  # exact tier, optional

cloudg/policies/ also ships Cloud Custodian policy packs (AWS governance, AWS security, Azure, GCP) runnable with custodian run independently of cloudg.

# Python API

CloudGEngine is the integration entry point — async-first with sync wrappers, built for embedding in larger systems (SIEMs, orchestration platforms, command extensions such as hol-guard).

from cloudg import CloudGConfig, CloudGEngine

config = CloudGConfig(providers=["aws"])
engine = CloudGEngine(config)
engine.on_finding = lambda f: forward_to_siem(f)

result = engine.run_pipeline_sync()
print(result.to_summary())

Working from existing scan outputs instead:

result = engine.run_from_reports_sync(
    {"prowler": ["./prowler-output/"], "trivy": ["./trivy.json"]},
    output_dir="./reports",
)
MethodDoes
collect()multi-provider asset collection → CollectionResult
scan(assets, edges)run enabled scanners + graph reachability → findings
ingest_reports(reports)parse existing scanner outputs → findings, nothing executed
normalise_findings(findings)dedupe, merge, score, compliance-map → ScanResult
analyze(assets, edges, findings)graph, ontology, RAG, Terraform → AnalysisResult
run_pipeline()everything → PipelineResult
run_from_reports(reports)ingest → normalise → reports → PipelineResult

Event hooks for streaming integration: on_phase_start, on_collection_complete, on_finding, on_scan_complete, on_analysis_complete, on_error. Exceptions inside a hook are swallowed so they cannot break the pipeline. Each scanner class also exposes its parser directly: ProwlerScanner.parse_report(path) and friends.

# Plugins

Custom collectors and scanners register through setuptools entry points — no core changes needed:

[project.entry-points."cloudg.collectors"]
mycloud = "my_package.collector:MyCollector"

[project.entry-points."cloudg.scanners"]
myscanner = "my_package.scanner:MyScanner"

A scanner plugin needs a run() -> list[Finding] method; collectors follow cloudg/collectors/base.py. PluginRegistry discovers entry points at startup and falls back to the built-ins for anything not overridden.

# Authentication

Every provider supports several methods, resolved in fixed priority order — the same config works on a laptop, in CI and on cloud compute.

ProviderMethods, most explicit first
AWSdirect keys → OIDC web identity federation (--aws-role-arn + --aws-web-identity-token-file) → named profile incl. SSO → default chain (env, cached SSO, instance role). STS assumption layers on top with --aws-external-id for the third-party-auditor pattern; multi-account fan-out via accounts + role_name.
Azureworkload identity federation → service principal (secret or certificate) → managed identity → DefaultAzureCredential (covers az login).
GCPcredentials file (service-account key or workload identity federation config) → application default credentials. --gcp-impersonate-sa layers impersonation on either.
